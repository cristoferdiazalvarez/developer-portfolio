# Developer portfolio delivery plan

Scope: build a new independent project in DEVELOPER-PORTFOLIO. Never modify BusinessOS or Atelier Commerce. GitHub repository creation, commits and push are authorized after checks. A new Vercel hosting project requires the owner's separate confirmation. No paid service, billing or database is needed.

1. Verify supplied projects and public personal information. Use authentic project screenshots with provenance. Do not infer employment, education, metrics or unconfirmed contact details.
2. Implement an original graphite/ivory/citrus editorial design: Spanish home, complete English version, two detailed case studies, organized stack, honest profile and actionable GitHub contact.
3. Add static SEO, per-language metadata, Person/CreativeWork JSON-LD, Open Graph image, sitemap and robots. Enable domain-dependent canonical URLs only after real public domain configuration.
4. Validate production build, strict TypeScript, lint, meaningful content tests, browser navigation/responsive/accessibility and real screenshots. Run Lighthouse when available; record limits accurately.
5. Review publication contents, confirm GitHub identity, create public developer-portfolio, commit/push and verify remote CI.
6. Prepare Vercel Hobby deployment with Node 22 and no database. Provide a concrete local/repository result, then request the one required hosting-creation confirmation.

Acceptance: actual project links/images, no fabricated biography or contacts, working keyboard navigation and reduced motion, complete ES/EN content, verified checks and clean repository. LinkedIn/email/CV remain centrally configurable and absent until confirmed by the owner.
